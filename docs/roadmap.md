## M1 · Probe — מדידת אמת

המטרה היא **להחליף השערות במספרים** לפני שכותבים את המסנן.

- [ ] התקנת השלד על השעון ועל הטלפון; איסוף דוחות "בדיקת מכשיר"
- [ ] `core:tracking`: ממשק `SpeedSource` + `RawSample`
- [ ] לוגר: הקלטה מקבילה של GNSS ישיר + Health Services בשעון, ו-GNSS בטלפון
- [ ] ייצוא ההקלטה לקובץ
- [ ] ארבעת הניסויים מ-[02-speed-accuracy](research/02-speed-accuracy.md#6-תוכנית-האימות-שלב-m1): עמידה, מסלול 400 מ', יד מתנדנדת מול צמודה, ספרינטים
- [ ] מדידת צריכת סוללה בשעון לכל מקור
- [ ] דוח תוצאות ב-`docs/research/field-tests/` + עדכון יעדי הדיוק באפיון
- [ ] **הכרעה:** מקור ראשי בשעון, ופרמטרי המסנן

**דורש ממך:** כ-30 דקות בחוץ עם שני המכשירים.

## M3 · סנכרון + טלפון MVP

- [ ] `core:sync`: מעטפה, קידוד, round-trip
- [ ] `SyncEngine` בשעון, `SyncReceiver` בטלפון, אישורים ופיוס
- [ ] טלפון: היסטוריה, מסך ריצה עם גרף, טבלת דקה-דקה, מחיקה, יחידות
- [ ] בדיקות: ריצה בלי טלפון → חזרה לטווח; ניתוק באמצע העברה; התקנה מחדש של אפליקציית הטלפון

**בסוף M3:** ה-MVP המלא מהאפיון.

## שיטת עבודה

- **ענף `main` תמיד נבנה.** commit אחד לכל יחידת עבודה שלמה, עם גוף שמסביר למה.
- **tag מוער לכל אבן דרך** (`m1`, ‏`m2`…) ואחר כך לכל גרסה (`v0.2.0`).
- **מסמכים מתעדכנים באותו commit** שמשנה את מה שהם מתארים.
- **החלטות כבדות** נכנסות ל-[decisions.md](architecture/decisions.md) לפני שמיישמים אותן.
