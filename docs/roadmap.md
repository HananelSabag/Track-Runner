# Roadmap

כל אבן דרך מסתיימת במשהו שאפשר להתקין ולהשתמש בו, ב-tag ב-git, ובעדכון של המסמכים הרלוונטיים.

| | אבן דרך | תוצר | מצב |
|---|---|---|---|
| **M0** | מחקר, אפיון, שלד, שדרוג | הריפו הזה | ✅ |
| **M1** | **הקלטה ראשונה** — לוגר + מדידת אמת | אימון אמיתי מוקלט מהשעון שלך | ממתין לך |
| **M2** | שעון MVP — ריצה וכדורגל | שני המצבים עובדים על השעון, עצמאית | 🟡 מותקן על השעון, עוד לא הוקלט אימון אמיתי |
| **M3** | סנכרון + טלפון MVP | היסטוריה, גרפים וניתוח אימון בטלפון | 🟡 מותקן, והסנכרון עבד על המכשירים האמיתיים |
| **M4** | שידור חוזר ומפת חום | המסלול מתנגן על המגרש | 🟡 בנוי, על אמולטור |

🟡 = הקוד כתוב, נבנה ונבדק על אמולטורים, אבל עוד לא רץ על המכשירים האמיתיים. אבן דרך נסגרת (✅ + tag) רק אחרי שעבדה אצלך.

**למה M2–M4 התקדמו לפני ש-M1 נסגר:** M1 תלוי בך — ספרינטים ואימון אמיתיים. כשלא היית בבית ביקשת לא לחכות, אז נבנה כל מה שלא תלוי במדידות. מה שכן תלוי בהן (כיוונון ספים, מסנן) נשאר פתוח ומסומן.
| **M5** | ליטוש | Tile, שיאים, ייצוא, onboarding | |
| **M6** | Duo (אם יוחלט) | שילוב שעון + טלפון בריצה | |

- [x] אפיון מוצר ו-UX, ‏mockups לשני המצבים
- [x] ארכיטקטורה ויומן החלטות
- [x] ריפו + שלד Gradle רב-מודולי
- [x] **שדרוג לגרסאות האחרונות** (AGP 9.4.1, ‏SDK 37, ‏Wear Compose 1.7.1)
- [x] אמולטור Wear OS; האפליקציה הורצה עליו
- [x] מסך "בדיקת מכשיר" בשתי האפליקציות
- [x] לוגו, אייקונים ופלטה (גרסה 2)

## M1 · הקלטה ראשונה

**הצעד הראשון כבר נעשה: [מבחן הספרינט](spec/sprint-test.md).** הוא הפיצ'ר הראשון שקורא GPS אמיתי מהשעון, והוא שומר כל דגימה — כך שכל ספרינט שתעשה הוא גם מדידת אמת ראשונה של השעון.

- [x] הרשאת מיקום עם הסבר
- [x] קריאת GNSS ישירה מהשעון (`GnssSpeedSource`)
- [x] מבחן ספרינט מקצה לקצה: מוכנות, ספירה לאחור, סיום אוטומטי, תוצאה
- [x] ציון אמינות עם 31 בדיקות, כולל כל תרחישי "תוצאת שווא"
- [x] שמירת הדגימות הגולמיות על השעון
- [x] הותקן על השעון האמיתי
- [x] **נתונים ראשונים מה-GPS האמיתי** (הליכות, 11.10) ← [נמצא ותוקן באג](research/field-tests/2026-10-11-first-real-gps.md): המקלט מדווח דיוק קבוע חסר משמעות
- [ ] **ספרינטים אמיתיים בחוץ** ← משיכת הקבצים ← כיוונון הספים

המטרה: **אימון אמיתי אחד מוקלט**, כדי להחליף השערות במספרים לפני שמכווננים את המסנן.

- [x] צימוד השעון ב-Wireless debugging; התקנה; [דוח "בדיקת מכשיר" מהשעון האמיתי](research/field-tests/2026-10-10-watch-device-report.md)
- [x] הרשאות (מיקום, דופק, התראות) עם הסברים
- [x] foreground service שמקליט לקובץ, עם Ongoing Activity
- [x] מסך הקלטה: התחל / מהירות חיה / סיום
- [x] ההקלטה היא קובץ טקסט שאפשר למשוך למחשב (`run-as … cat files/sessions/<id>.fast`)
- [x] התקנה על השעון (0.4.1) ועל הטלפון (0.3.1)
- [ ] **אימון אמיתי אחד**
- [ ] **הרצת ההקלטה דרך מנוע הניתוח** — לראות אם זיהוי המנוחה והספרינטים תואם למה שקרה באמת
- [ ] מדידת סוללה באימון של שעה
- [ ] `SpeedSource` שני: Health Services, מוקלט במקביל ל-GNSS הישיר (נדחה עד שיש נתונים אמיתיים להשוות מולם)
- [ ] ארבעת ניסויי הדיוק מ-[02](research/02-speed-accuracy.md#6-תוכנית-האימות-שלב-m1)
- [ ] **הכרעה:** מקור ראשי, פרמטרי המסנן, וכיוונון ספי המנוחה

**דורש ממך:** להפעיל Wireless debugging כשאתה בבית, ואימון אחד עם השעון (ריצה או כדורגל).

## M6 · Duo (אם יוחלט)

שילוב GNSS של הטלפון בריצה, החלקה בדיעבד ממוזגת, ומדידה אם זה באמת משפר.

## אחר כך (לפי עניין)

זיהוי פרצים ממד התאוצה (האצות, שינויי כיוון) · Health Connect · חיישנים חיצוניים (רצועת דופק, GNSS של 10Hz) · Live Updates ל-Wear OS 7.

## שיטת עבודה

- **ענף `main` תמיד נבנה.** commit אחד לכל יחידת עבודה שלמה, עם גוף שמסביר למה.
- **tag מוער לכל אבן דרך** ואחר כך לכל גרסה.
- **מסמכים מתעדכנים באותו commit** שמשנה את מה שהם מתארים.
- **החלטות כבדות** נכנסות ל-[decisions.md](architecture/decisions.md) לפני שמיישמים אותן.
