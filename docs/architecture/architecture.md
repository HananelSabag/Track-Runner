# ארכיטקטורה

## מבט-על

```
┌──────────────── שעון (:wear) ────────────────┐        ┌────────────── טלפון (:mobile) ──────────────┐
│  UI (Wear Compose M3)                         │        │  UI (Compose M3)                            │
│     ▲ StateFlow                               │        │     ▲ StateFlow                             │
│  ViewModels                                   │        │  ViewModels                                 │
│     ▲                                         │        │     ▲                                       │
│  TrackingService (foreground) ── מנוע המעקב   │◄─live─►│  TrackingService (מצב Duo / טלפון לבד)      │
│     │                                         │ Message│     │                                       │
│  Room (מקור האמת)  ──► SyncEngine ────────────┼─Data──►│  SyncReceiver ──► Room (מקור האמת)          │
└───────────────────────────────────────────────┘ Client └─────────────────────────────────────────────┘
                         ▲                                              ▲
                         └──────────── מודולי core משותפים ─────────────┘
```

שני עקרונות מחזיקים את הכול:
- **Room הוא מקור האמת בכל מכשיר.** ה-UI קורא רק ממנו (וממצב המנוע החי), אף פעם לא ישירות מחיישן או מהרשת.
- **המנוע חי בשירות, לא במסך.** ההקלטה ממשיכה כשהמסך כבוי, כשהאפליקציה ברקע, וכשה-Activity נהרס.

## מודולים

```
Track-Runner/
├── wear/                 אפליקציית השעון
├── mobile/               אפליקציית הטלפון
└── core/
    ├── model/            ✅ טיפוסי דומיין (Kotlin טהור)
    ├── diagnostics/      ✅ קריאת יכולות חומרה (Android)
    ├── tracking/         ⏳ מנוע המהירות: מקורות, מסנן, סטטיסטיקות (Kotlin טהור)
    ├── data/             ⏳ Room: ישויות, DAO, מאגרים (Android)
    └── sync/             ⏳ פורמט ההעברה והפרוטוקול (Kotlin טהור + מעטפת Data Layer)
```
✅ קיים בשלד · ⏳ מתוכנן

**כללי תלות:**
- `wear` ו-`mobile` לא תלויים זה בזה. כל מה שמשותף עובר דרך `core`.
- מודולי `core` לא תלויים באפליקציות, ולא ב-UI.
- **כל מה שאפשר — Kotlin טהור.** המסנן, הסטטיסטיקות והפרוטוקול לא מכירים את Android, ולכן נבדקים בבדיקות JVM מהירות בלי אמולטור. זה מה שמאפשר את בדיקות ההרצה-החוזרת של ריצות מוקלטות.
- **בתוך כל אפליקציה: חבילות לפי פיצ'ר** (`run/`, `history/`, `devicecheck/`, `theme/`), לא לפי שכבה. פיצול לפיצ'ר-מודולים רק אם יהיה בזה צורך אמיתי — בגודל הזה זה רק מאט את ה-build.

## מנוע המעקב (`core:tracking`)

```
SpeedSource (ממשק) ──► דגימות גולמיות מתויגות ──┬──► נשמרות כמו שהן (Room)
  ├ WatchGnssSource                              │
  ├ HealthServicesSource                         └──► SpeedFilter (Kalman) ──► TrackingState ──► UI
  └ PhoneGnssSource / RemotePhoneSource                     │
                                                            └──► SessionStats (מקס', שיאי חלון, ממוצע, מרחק)
```

- **`SpeedSource`** — ממשק אחד, `Flow<RawSample>`. המימושים חיים באפליקציות (הם תלויי-פלטפורמה); המנוע רואה רק את הממשק. הוספת מקור חדש (חיישן חיצוני, למשל) לא נוגעת במסנן.
- **`RawSample`** — מקור, זמן GNSS ‏(UTC), זמן מונוטוני מקומי, מהירות, אי-ודאות מהירות, מיקום, אי-ודאות מיקום, כיוון.
- **`SpeedFilter`** — מקבל מדידות מכמה מקורות, מחזיר הערכה אחת + אי-ודאות. בלי מצב גלובלי, דטרמיניסטי: אותן דגימות → אותה תוצאה. זה התנאי לבדיקות ההרצה-החוזרת.
- **`Smoother`** — מעבר קדימה-אחורה על ריצה שלמה בסיומה. מייצר את המספרים שנשמרים בהיסטוריה.
- **`algorithmVersion`** — כל סטטיסטיקה נגזרת מסומנת בגרסה. שינוי במסנן מעלה את הגרסה, ועבודת רקע מחשבת מחדש ריצות ישנות מהגולמי.

## מודל הנתונים (`core:data`)

| ישות | שדות עיקריים |
|---|---|
| `Session` | `id` (UUID), התחלה/סיום (UTC), משך פעיל, פרופיל, מכשיר המקור, מקורות שהשתתפו, `syncState`, `recovered`, גרסת אפליקציה |
| `RawSample` | `sessionId`, מקור, `tUtcMs`, `tMonoNs`, מהירות, אי-ודאות, lat/lon/alt, דיוק אופקי, כיוון |
| `SessionStats` | `sessionId`, `algorithmVersion`, מרחק, ממוצע, מקס' + מתי, שיא 3 שנ', שיא 10 שנ' |
| `Marker` | `sessionId`, זמן, סוג (הקפה / השהיה / המשך) |

- `Session` ו-`RawSample` הם **עובדות** — לא משתנים אחרי הסיום. `SessionStats` הוא **נגזר** — ניתן לחישוב מחדש בכל רגע.
- אותה סכמה בשני המכשירים; ההבדל רק במה נשמר לאורך זמן (השעון שומר N ריצות אחרונות, הטלפון הכול).
- ‏3,600 שורות לשעת ריצה למקור — זניח ל-SQLite, אז דגימות נשמרות כשורות רגילות ולא כ-blob.

## סנכרון (`core:sync`)

הפרוטוקול המלא ב-[03-watch-phone-sync.md](../research/03-watch-phone-sync.md). מבנה הקוד:

- **`SessionEnvelope`** — מבנה ההעברה: `schemaVersion`, ה-`Session`, והדגימות כמערכים עמודתיים. מקודד כ-JSON ודחוס ב-gzip. Kotlin טהור, עם בדיקת round-trip.
- **`SyncEngine`** (שעון) — מכונת המצבים `FINISHED → SYNC_PENDING → SYNCED`, כתיבה ל-`DataClient`, טיפול באישורים, ופיוס.
- **`SyncReceiver`** (טלפון) — `WearableListenerService`: שמירה בטרנזקציה, upsert לפי UUID, כתיבת אישור.
- **נתיבים:** ‏`/fast/session/{uuid}`, ‏`/fast/ack/{uuid}`; הודעות: ‏`/fast/live/*`, ‏`/fast/cmd/*`; ‏capability: ‏`fast_phone`, ‏`fast_watch`.

`schemaVersion` קיים מהיום הראשון כי שעון וטלפון יתעדכנו בזמנים שונים, וצד חדש חייב לדעת לקרוא צד ישן.

## שכבת ה-UI

זרימה חד-כיוונית: המסך מקבל `StateFlow<UiState>` מה-ViewModel ושולח אליו אירועים. ה-ViewModel לא מחזיק לוגיקה עסקית — הוא ממפה מצב מהמנוע ומהמאגרים.

- **שעון:** `AppScaffold` אחד → `ScreenScaffold` לכל מסך → `TransformingLazyColumn` לרשימות. ניווט: Navigation 3 עם `SwipeDismissableSceneStrategy`. לפי הסקיל הרשמי של גוגל.
- **טלפון:** Compose Material 3, ‏Navigation 3, מסך מלא (edge-to-edge), כהה בלבד.
- **צבעי המותג** מוגדרים פעם אחת בכל אפליקציה (`theme/FastTheme.kt`) ותואמים ל-[brand.md](../brand/brand.md).

## שירותים והרשאות

| | שעון | טלפון |
|---|---|---|
| Foreground service | `health\|location` | `location` |
| הרשאות | מיקום מדויק, זיהוי פעילות, התראות | מיקום מדויק (רק ל-Duo/הקלטה), התראות |
| רקע | Ongoing Activity; ‏WorkManager לפיוס | `WearableListenerService`; ‏WorkManager לחישוב מחדש |

הרשאות מבוקשות ברגע שצריך אותן ועם הסבר, לא בהפעלה הראשונה. הטלפון לא מבקש מיקום בכלל עד שמפעילים Duo.

## החלטות עיצוב שכדאי לזכור

- **למה לא KMP?** אין iOS בתוכנית. Kotlin טהור ב-`core` נותן את רוב התועלת (בדיקות מהירות, הפרדה נקייה) בלי המורכבות.
- **למה לא ענן?** פרטיות ואפס תחזוקה. המחיר: אין גיבוי אוטומטי מעבר לגיבוי של Android — מכוסה ע"י ייצוא.
- **למה לא convention plugins עכשיו?** ארבעה מודולים. כשנגיע לשישה-שבעה וה-`build.gradle.kts` יתחילו להשתכפל, נוסיף `build-logic`.
